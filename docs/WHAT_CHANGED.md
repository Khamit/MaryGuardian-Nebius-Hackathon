# What existed before the submission period, and what changed

**Baseline (before Aug 26, 2026):** a macOS-first C++ application that sorted documents: an incremental folder indexer with SQLite and SHA-256 dedup, rules-based extraction of dates, amounts and numbers, MuPDF and Office text extraction, a loopback HTTP server with a per-run token, the Guardian (action allow-list, PII detection, prompt-injection scan, JSONL audit), a local Qwen classifier through llama.cpp, optional local OCR, and a single-page UI. It had no cloud-model backend, no cross-document checks and no page-level evidence view.

**Significantly updated during the submission period.** The commit history since the start of the period: `git log --since=2026-08-26 --stat`.

| Area | Change |
|---|---|
| Models | New `LlmClient` abstraction; Nemotron on Nebius Token Factory with Nano/Super/Ultra tier routing; reasoning-model handling (token headroom, retry on empty `content`, `json_object` fallback); drafts and library questions routed through the same gateway |
| Privacy | New PII-masking gateway (reversible, per-request, fail-closed leak check); `standard` and `strict` levels covering secrets, company names, document numbers, names and addresses by label; protected terms; hourly request budget; outbound ledger with masked previews |
| Extraction | `ClassificationRules`: weighted phrase rules in English, Russian and Kazakh for invoices, receipts, contracts, statements, tax, payroll, shipping and customs documents, certificates, product catalogs and datasets, plus date, number, issuer, amount and currency extraction (Cyrillic month names are parsed by hand because `std::regex` is byte-based); two new document types (product catalog, product dataset); escalation to Super for low-confidence documents; every proposed value validated in code before it is stored |
| Consistency & fraud detection | New `Consistency` module: payee-account baseline (your confirmed account, otherwise trust on first use), "bank details changed" notices that never count as confirmation, IBAN checksum, reused invoice numbers, outlier amounts, date checks; salted account fingerprints instead of raw numbers; *Confirmed by phone* registry; whole-library recomputation after every scan, correction or confirmation; *Needs attention* view and risk badges |
| X-ray | New page view: PDF page rendered with evidence boxes (found fields, differing account, masked spans, AI-instruction phrases, white-on-white lines), "Cloud view", animated replay; *Draft verification request* behind human approval |
| Learning | Correction memory per company: document type and collection fixes are remembered and applied to future documents |
| Always-on | Background folder watcher with a cheap directory signature and a "file still being written" guard; parallel classification; in-memory scan index with batched writes |
| Platform | Linux port (portable SHA-256, CMake), platform layer for sockets, time, randomness and signals |
| UI | Privacy tab (what the cloud saw), Settings tab (backend, model check, optional local-model downloads), Activity tab (files not re-read, calls, tokens, tokens saved), X-ray window |
| Data & tests | Synthetic dataset generated by the binary itself (24 documents: a changed-bank-account scenario, a hidden-instruction invoice, duplicates, expiring and expired documents, Russian text and CSV); unit and integration tests for masking, consistency, X-ray, field validation, correction memory and the demo set; end-to-end leak test against a mock OpenAI server |
